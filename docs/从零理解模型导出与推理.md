## 第一部分：最底层的基础概念

### 1.1 「模型」和「权重」到底是什么

一个神经网络模型，本质上是**一层层数学运算堆起来**的东西：矩阵乘法、加法、以及一些非线性的函数（激活函数）。

所谓「训练」，就是给模型看大量「输入图片 → 正确答案」，让它**自动调整这些运算里的数字**，直到输出的答案越来越接近正确答案。这些被调整出来的数字，就是**权重（weights）**。

所以 `.pt` 文件里保存的，主要就是两样东西：

1. **网络结构**（有哪些层、每层怎么连）；
2. **权重数值**（每个连接上的那个数字是多少）。

模型文件 ≈ 结构 + 数字。没有数字，结构就是一堆空壳；没有结构，数字也不知道该往哪放。

### 1.2 训练 vs 推理

- **训练（training）**：不断改权重，让模型变聪明。慢，需要大量数据和 GPU。
- **推理（inference）**：权重已经定死，只做「输入一张图 → 算出结果」这一件事。快。

本次作业只做**推理**。我们拿到的 `best.pt` 是别人/上一份作业已经训练好的权重，我们不改它，只用它算结果。

### 1.3 前向传播是什么

「推理」的另一个名字叫「**前向传播（forward propagation）**」。

前向传播 = 把输入数据，一层一层地喂给网络，每一层算出一个结果，再传给下一层，最后一层输出最终结果。

这就是选做题里「在 Excel 里做前向传播」的含义：把网络每一层的乘法加法，用 Excel 的格子一个格子地算出来，你会直观看到「输入 → 隐藏层 → 输出」的数字是怎么流动的。

### 1.4 张量（tensor）和形状（shape）

张量就是一个**多维数组**。它的「形状」描述每一维有多大。

例如本次 ONNX 模型的输出形状是 `[1, 18, 8400]`：

- 第 1 维 `1`：一次推理 1 张图（batch）；
- 第 2 维 `18`：每个候选目标有 18 个数字；
- 第 3 维 `8400`：一共有 8400 个候选位置。

理解形状是理解所有代码的关键。后面 `infer_onnx.py` 里所有的切片操作，都是在「从这 18 个数字里，取出框、类别、关键点」。

### 1.5 图片是怎么变成数字的

一张彩色图片，在计算机里是一个三维数组：`高(H) × 宽(W) × 3`。最后的 `3` 是三个颜色通道。

- 人类习惯说 `HWC`（高、宽、通道）；
- 深度学习框架 PyTorch 习惯用 `CHW`（通道、高、宽）。

所以推理前要做一次 `HWC → CHW` 的转置。

颜色通道还有个坑：OpenCV 读图默认是 **BGR**（蓝绿红），但模型训练时通常用 **RGB**（红绿蓝）。顺序不对会检测不准，所以还要做一次 `BGR → RGB`。

最后，像素值本来是 0~255 的整数，模型通常希望输入是 0~1 的小数，所以要 `/255.0` 做归一化。

## 第二部分：YOLO 是怎么检测目标的

### 2.1 目标检测要回答三个问题

给定一张图，目标检测要输出：

1. **框（box）**：目标在哪里（一个矩形）；
2. **类别（class）**：目标是什么；
3. **置信度（confidence）**：模型有多确定。

本次模型还多了第 4 个：**关键点（keypoints）**，也就是装甲板四个角的坐标。

### 2.2 YOLO 的思路：一次前向，输出所有候选

传统方法可能要「先找区域、再对每个区域分类」，很慢。YOLO 的思路是：**把整张图缩到固定尺寸（比如 640×640），只做一次前向，网络一次性输出一大堆候选框**，每个候选框都带着「框坐标 + 类别分数 + 关键点」。

这就是为什么输出是 `[1, 18, 8400]`：

- 网络把 640×640 的图划分成多层网格（80×80、40×40、20×20），加起来 `80²+40²+20² = 8400` 个候选位置；
- 每个候选位置输出 `18` 个数字：`4` 个框坐标 + `6` 个类别分数 + `8` 个关键点（4 个点 × 2 个坐标）。

即：`18 = 4 + 6 + 8`。

### 2.3 后处理：从 8400 个候选里挑出真正有用的

网络不会直接给出「就是这一个框」，而是给出 8400 个候选，其中绝大多数是垃圾。所以推理后要做三步：

1. **置信度过滤**：只保留类别分数高于阈值（本次是 0.25）的候选。
2. **NMS（非极大值抑制）**：同一个目标可能被多个候选框框住，NMS 把重叠度过高的重复框去掉，只留分数最高的那个。
3. **坐标映射**：把候选框的坐标从「640×640 的缩略图坐标」换算回「原图坐标」。

## 第三部分：模型格式与导出

### 3.1 为什么有这么多格式

训练框架（PyTorch）和部署环境（手机、服务器、嵌入式设备）往往不一样。为了「一次训练，到处部署」，人们定义了中间格式，把模型「翻译」成通用的表示。

| 格式 | 一句话理解 |
|------|-----------|
| `.pt` | PyTorch 原生格式，训练和实验最方便 |
| `.onnx` | 通用交换格式，跨框架、跨平台 |
| `.torchscript` | PyTorch 自家的部署格式 |
| `.engine` (TensorRT) | NVIDIA GPU 专用，极致加速 |
| OpenVINO | Intel 硬件专用 |

### 3.2 ONNX 是什么，导出做了什么

ONNX = Open Neural Network Exchange（开放神经网络交换）。它把模型描述成一个**标准的计算图**：每个节点是一个算子（卷积、加法、ReLU……），节点之间是数据流。

导出 `.pt → .onnx`，本质是：

> 把 PyTorch 的模型结构和权重，翻译成 ONNX 标准格式，存成一个文件。

翻译过程中权重数值不变，所以**精度几乎不受影响**（本次实测两种格式检测结果一致，就证明了这一点）。

### 3.3 本次导出具体做了什么

看 `export.py`：

```python
model.export(format="onnx", imgsz=640, opset=12, simplify=True, dynamic=False)
```

- `format="onnx"`：导出为 ONNX；
- `imgsz=640`：固定输入 640×640；
- `opset=12`：使用第 12 版算子集；
- `simplify=True`：简化计算图；
- `dynamic=False`：固定 batch 和尺寸，使输出形状确定（`[1,18,8400]`），方便写后处理。

## 第四部分：推理代码逐行拆解

推理 = 预处理 → 前向 → 后处理。`infer_onnx.py` 就是按这个顺序写的。

### 4.1 预处理（preprocess）

```python
img, r, dwdh = letterbox(img0, (640, 640))   # 等比缩放 + 灰色填充
img = img[:, :, ::-1].transpose(2, 0, 1)      # BGR -> RGB, HWC -> CHW
img = img / 255.0                             # 归一化
```

- `letterbox`：把原图**等比**缩放到能放进 640×640，不足的部分用灰色（114,114,114）填充。这样不会把图压变形。
- `[:, :, ::-1]`：把 BGR 通道顺序倒过来变成 RGB。
- `.transpose(2,0,1)`：HWC 转 CHW。
- `/255.0`：像素 0~255 归一化到 0~1。

### 4.2 前向（forward）

```python
outputs = session.run(None, {input_name: img_tensor})
```

把预处理好的张量喂给 ONNX Runtime，得到输出 `[1,18,8400]`。

### 4.3 后处理（postprocess）

```python
preds = np.squeeze(outputs[0]).T          # [1,18,8400] -> [8400,18]
boxes   = preds[:, :4]                    # 前 4 个数字：框
scores  = preds[:, 4:10]                  # 中间 6 个：类别分数
kpts    = preds[:, 10:]                   # 最后 8 个：关键点
```

然后：

1. `class_ids = argmax(scores)`：取分数最高的那个类别。
2. `confidences = max(scores)`：最高分数就是置信度。
3. 过滤低于阈值的候选，做 NMS。
4. 把坐标从 640 空间映射回原图：`x1 = (cx - w/2 - dw) / r`（`r` 是缩放比，`dw/dh` 是填充量）。

### 4.4 计时怎么测才公平

不能只跑一次就报时间，因为第一次可能包含模型加载、CUDA 初始化等开销。正确做法：

1. 先**预热**（跑 10 次，让 GPU 进入稳定状态）；
2. 再**连续跑 30 次取平均**；
3. 两种格式用**相同的输入、阈值、硬件**。

这就是 `infer_pt.py` 和 `infer_onnx.py` 里 `Warm-up + 30 runs` 的意义。

## 第五部分：GPU、CUDA、cuDNN、onnxruntime 的关系

### 5.1 为什么需要 GPU

神经网络主要是大量矩阵乘法，GPU 有几千个核心，能并行算，比 CPU 快很多。

### 5.2 CUDA 和 cuDNN 是什么

- **CUDA**：NVIDIA 的 GPU 编程平台，让你能在 GPU 上写通用计算。
- **cuDNN**：NVIDIA 为深度学习专门优化的库（卷积等算子的高性能实现）。
- **cuBLAS**：NVIDIA 的矩阵运算库（`cublasLt64_12.dll` 就是它的动态链接库）。

PyTorch、onnxruntime 在 GPU 上跑，底层都会调用这些库。

### 5.3 onnxruntime 的 provider 是什么

onnxruntime 是「执行 ONNX 模型的引擎」。它的 provider 就是「用哪个后端来执行」：

- `CPUExecutionProvider`：用 CPU；
- `CUDAExecutionProvider`：用 NVIDIA GPU；
- `TensorrtExecutionProvider`：用 TensorRT 加速。

推理时指定 provider 列表，它会按顺序尝试，第一个可用的就是实际执行的后端。

### 5.4 本次 `cublasLt64_12.dll` 缺失是怎么回事

`onnxruntime-gpu` 的 CUDA provider 依赖 `cublasLt64_12.dll`，但系统里没有单独装 CUDA 运行库。

好消息是：**PyTorch 安装包自带了这些 DLL**（在 `torch/lib/` 目录下）。所以只要在导入 onnxruntime **之前**，把 `torch/lib` 加进环境变量 `PATH`，onnxruntime 就能找到并复用这些 DLL。

```python
torch_lib_path = os.path.join(os.path.dirname(torch.__file__), "lib")
os.environ["PATH"] = torch_lib_path + os.pathsep + os.environ.get("PATH", "")
```

`shape_test.py` 之前没加这一段，所以报错；修复后就能正常用 GPU 了。

## 第六部分：本次作业遇到的每一个错误及其底层原因

### 错误 1：ONNX 推理检测数为 0

**现象**：用 `assets/result_sample3.png` 测试时，ONNX 一个目标都检测不到。

**底层原因**：这张截图里装甲板偏小、距离较远。经过 letterbox 等比缩小后，模型对它的**置信度只有约 0.076**，而当时阈值是 0.15，于是所有候选都被过滤掉了。

**教训**：不是代码错了，是「测试图 + 阈值」不匹配。换一张目标清晰的图（或调低阈值）即可。

### 错误 2：`cublasLt64_12.dll` 缺失

见 5.4。核心是「onnxruntime 的 GPU 依赖没装，但 PyTorch 已自带，只需加 PATH 复用」。

### 错误 3：无检测时打印 `⚠️` 触发 UnicodeEncodeError

**现象**：`infer_onnx.py` 的警告文本里有 emoji，在 GBK 控制台下打印时报错。

**底层原因**：Windows 中文控制台默认用 GBK 编码，而 `⚠️` 这个字符不在 GBK 里，Python 打印时无法编码，于是抛异常。

**教训**：脚本日志尽量用纯 ASCII（英文），或者显式把输出编码设为 UTF-8。

### 错误 4：`.to("0")` 报 Invalid device string

**现象**：把设备字符串写成 `"0"`，`YOLO(...).to("0")` 报错。

**底层原因**：PyTorch 的 `.to()` 认识的字符串是 `"cpu"`、`"cuda"`、`"cuda:0"`，不认识 `"0"`。要写 `"cuda:0"` 或整数 `0`。

## 第七部分：Git/GitHub 提交流程

### 7.1 为什么用 git

git 是版本管理工具，能记录每一次修改，方便回退和协作。`.gitignore` 用来排除「不该上传」的文件（比如虚拟环境 `.venv`、本地视频 `videos/`、运行输出 `outputs/`）。

### 7.2 本次提交做了什么

本次提交前，`export.py`、`infer_onnx.py` 等新文件已经写好，但还没 commit。完整的流程是：

```powershell
git add .
git commit -m "完成 .pt 导出 ONNX、推理与性能对比"
git push origin main
```

同时把模型文件 `best.pt`、`best.onnx` 从 `.gitignore` 里放出来，这样它们也能上传到仓库（两个文件都不大，无需 Git LFS）。

## 第八部分：选做题方向（Excel 前向传播）

选做题要求阅读「井字棋强化学习高手」一文，并尝试在 Excel 里做前向传播。

思路提示：

1. 把网络看成「一层矩阵乘法 + 一层激活函数」重复几层；
2. 在 Excel 里用一列放输入、几列放权重、用 `SUMPRODUCT` 或矩阵公式算出每层输出；
3. 最后输出的分数，再经过一个 softmax 或直接取最大，就是「模型的选择」。

这一步会让你彻底理解 1.3 讲的「前向传播 = 一层层算下去」到底在算什么。
